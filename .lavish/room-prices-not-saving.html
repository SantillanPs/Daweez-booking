01

Where the prices went

Read left to right. The gold lane is what really happened; the red lane is what should have happened.

Read on another PC and the prices are gone. A different browser, a cleared cache or a new laptop starts from the database — which is empty. Only this one machine remembers them.

02

The cause is one line, in two places

The database column rooms.id is text and holds values like room-3. Both new write functions try to read it as a uuid — and room-3 is not a uuid.

works

Breakfast price — saved fine

UPDATE public.rooms
   SET breakfast_price = NULLIF(p_price, 0)
 WHERE id = p_room_id;        -- text = text ✓
Room 3 breakfast is ₱300 in the database today. This is how the file already worked, so it saved.
breaks

3 / 6 / 12-hour prices — rejected every time

DECLARE
  v_id uuid := NULLIF(p_room_id,'')::uuid;  -- ✗ "room-3"
BEGIN
  UPDATE public.rooms SET hour3_price = …
   WHERE id = v_id;          -- never reached
400 Bad Request — invalid input syntax for type uuid: "room-3"

This exact mistake has been fixed once before. The booking write functions had the same uuid-vs-text fault in August 2026 and it was repaired in two migrations — 20260816150000 and 20260816160000. The short-stay function was written afterwards and brought it back.

03

The second break, which you have not seen yet

The 3/6/12 save is not the only one failing. The board price save calls a function that does not exist in the database at all — it answers 404 Not found.

The board-price write function update_room_rate was never created in the live project — it is missing from the database's migration history entirely. So every room price edit you have made in Settings has gone to the browser and nowhere else. The new price shows on screen because the browser paints it over the old one.

04

The repair — three steps, in this order

1
Fix the short-stay function so it stops treating the room id as a uuid
One line: compare id = p_room_id directly, exactly like the breakfast function that already works. Run it as one SQL block — safe to run twice.
2
Create the missing board-price function
The same text-id treatment, plus the one-price rule the app already sends (it writes the same figure into both price columns).
3
Fix the two migration files in the repo so this cannot come back
The files 20260920120000_add_short_stays.sql and 20260826120000_update_room_rate_rpc.sql carry the same uuid fault — and the paste-file RUN-THESE-THREE-2026-09-23.sql would re-break it on any fresh project.

Your typed prices are not lost. They are still in this browser. Easiest is to re-type them once after the repair (a few rooms). If you would rather not, keep this machine's browser open and I will walk you through lifting them out before anything is cleared.
