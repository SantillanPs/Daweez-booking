The room-price bug is not the only one

Five more stores fail the same way — two of them even worse. This is what “no browser storage” really buys you.

StoreWhat happens when the database refuses the saveStaff see
Inventory
and cleaning checklist		 The refusal is never even looked at. The code writes the browser copy first and never reads the answer back — the database library reports a refusal in the result rather than throwing, so nothing catches it. silence
Tabs & lines, expenses, partners, menu Noticed, written to the browser console, then saved to the browser anyway. This is exactly the room-price pattern. “saved”
Bookings and feed links Same fallback, on purpose — this is the one that lets the desk keep taking a booking with no internet. offline save

An inventory or cleaning save can be silently lost today, and the screen still shows the new number. Nobody has reported it because nothing ever says it happened. Removing the browser copies fixes this class of bug everywhere, not just for prices.

03

What I would build, in this order

1
Group A — delete the browser copies, make every failed save speak
One store at a time, each with its own check: a save that does not reach the database shows a red message where the button was, and the screen stops pretending. Biggest single win: inventory and cleaning start telling the truth.
2
Group B — give the shared rates and the payment accounts a home in the database
Two small tables (or one settings table) plus their writers, then the browser copies go. This is what makes Settings mean the same thing on every PC — today the GCash number and both bank accounts on the bill are only in one browser.
3
The honest consequence, kept visible
With no browser store, the desk needs the internet for every save. If it drops, the app refuses and says so — it no longer quietly parks the change. Nothing is ever shown as saved that is not.
