The three things I built

A
One address cannot live on two rooms. The Channels screen now says so twice — a line above the Save button naming the rooms, and a refusal on Save that says the same words. It names the rooms, never the URL, because 60 characters of link tells the desk nothing.
Rule in utils/feedUrls.ts.
B
The blank rows cannot come back. They were written by the screen itself: every room draws two empty boxes, and saving stored them. Saving now stores only links that have an address — and clearing a box removes its feed, so "forget this link" and "never had one" end in the same place.
In db.saveFeeds.
C
The nine became one. The surviving Airbnb calendar hangs off Room 1, because a calendar shared by the whole house is the house's, not a room's — so an imported stay now lands on one room the desk can move, instead of blocking all ten.
Migration 20260930170000_one_feed_per_address.

Why this answer, whichever the listing is

  • If it is the whole house — one feed is exactly right, and a reservation now takes one room instead of the building.
  • If each room really has its own listing — the nine copies were all the same address, so at most one could have been right; nothing was lost by removing eight. Paste each room's own link into Settings → Channels and the new guard will confirm every one is different.
  • Either way, the download is 1× instead of 9×, and Analytics and Expenses stop waiting ~7 seconds on that run.

No booking, no money and no setting was touched — only the channel table and the rule that guards it.
